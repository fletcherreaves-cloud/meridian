## The constraint: three pushes, not thirty-eight

Owner asked whether we can "get ahead of this by being more selective in our builds."
**We cannot, and this is the second time that framing has been tried.** Recorded so it is
not tried a third time:

- The limit is `api-deployments-free-per-day` = **100 deployments/day**, and the limiter runs at
  deployment **CREATION**, before the ignore step. A skipped build still spends one.
- Build-time quota is at **5%** (5 h of 100 h; 0 s billable). Never close to binding.
- The `ignoreCommand` was added the morning of 08-21 on exactly this assumption. **The cap was hit
  again the same evening.**
- Measured 2026-08-23: **38 commits to `main` in 24 h**, and **95 live `claude/*` branches** on the
  remote, each of which cost >= 1 deployment when pushed.

**The only lever is FEWER PUSHES.** Commit freely locally; push once per PR when it is ready to
open. Tomorrow's shape: **push 1** = docs/dispatches batched into one commit; **push 2** = small
infra batched into one PR; **push 3** = one substantive item, finished.

⚠️ Deleting the 95 stale branches recovers **no** deploy budget — only pushes cost. It is hygiene,
not a fix. Do not schedule it expecting a payoff.

   recorded (`vercel.json` `git.deploymentEnabled` needs exact branch names, ours are randomly
   suffixed; the dashboard Ignored Build Step skips *builds*, which does not skip the count).
   **Untried:** disconnect Vercel's Git integration and deploy from a GitHub Action gated on
   `paths-ignore: [memory/**, '**.md']`, so a push creates nothing Vercel-side and only an explicit
   `vercel deploy --prod` does. Repo precedent exists (`deploy.yml` -> GitHub Pages).
