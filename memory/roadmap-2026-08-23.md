## The ranking principle, stated so it can be argued with

1. **Anything that can expose a person jumps the queue, regardless of size.** Meridian is heading
   to a second operator; a privacy defect stops being internal the day that happens.
2. **Then wrong numbers on screen.** A metric nobody can trust is worse than one that doesn't
   exist yet — four of the six fixes shipped 2026-08-23 were numbers that had been quietly wrong.
3. **Then foundations that unblock several things at once**, ahead of any single feature on top.
4. **Then value per hour.** A finished design with no blockers outranks a bigger idea with one.
5. **Owner-decision items held separately** — not deprioritised, just unschedulable. Batched so one
   sitting clears them.

⚠️ **Treat every unchecked backlog line as unverified.** Four were spot-checked while writing this;
**two were already false** (`staff_assignments` appears nowhere in the codebase;
`eom_count_progress_log` marked "never read" *is* read). Confirm against code before starting.
